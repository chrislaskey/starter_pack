# Client migrations

The SQLite schema of the synced `app_` tables, as the desktop and mobile
apps keep it: one file per migration that touches a synced table, generated by
`mix app.migrations` from `priv/repo/migrations` and committed. The
statements are exactly what the server's SQLite adapter ran, so a client
has the same tables and column types as the server: ids are `TEXT`,
datetimes are `TEXT` in UTC ISO 8601 with six fractional digits, booleans
are `INTEGER`. See "Schema source of truth" in `docs/design/offline-sync.md`.

Never edit a file here. Change the migration and run `mix app.migrations`;
`mix test` fails while a file is missing or stale.

A table is synced from the migration that creates it, or never. The
export keeps the statements of today's synced tables from every
migration, so marking a table as synced later, or unmarking one, would
rewrite files that clients have already applied. Add a new table instead.

## Applying them

A client keeps one SQLite file per server and account. On opening it:

1. Create its own two tables if they are missing, see below.
2. Apply every `.sql` file here whose version, the leading number of the
   file name, is not yet in `schema_migrations`, in version order. Each
   file is a list of statements ending in `;`, with comment lines starting
   `--`. Run the file's statements in one transaction and record the
   version, the same way Ecto does:

   ```sql
   CREATE TABLE IF NOT EXISTS schema_migrations (version INTEGER PRIMARY KEY, inserted_at TEXT);
   INSERT INTO schema_migrations (version, inserted_at) VALUES (20261025224658, '...');
   ```

The files are the whole schema, from the first migration, so a fresh file
and an old one both end up current.

## Tables the client adds itself

Two tables exist only on the client and are not exported, see "Client
bookkeeping" in `docs/design/offline-sync.md`:

```sql
CREATE TABLE sync_state (
  last_pulled_at TEXT,          -- the cursor: last_synced_at of the last row received
  last_pulled_id TEXT,          -- and its id
  server_purge_horizon TEXT     -- the oldest last_synced_at the server still has
);

CREATE TABLE sync_outbox (
  table_name TEXT NOT NULL,
  row_id TEXT NOT NULL,
  queued_at TEXT NOT NULL,
  attempts INTEGER NOT NULL DEFAULT 0,
  last_error TEXT,
  PRIMARY KEY (table_name, row_id)
);
```

Rows pulled from the server go in unchanged, column for column, with
`PRAGMA foreign_keys = ON` and each page applied in one transaction with
`PRAGMA defer_foreign_keys = ON`, since a page is in cursor order rather
than parent-first.
